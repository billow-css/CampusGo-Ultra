# Windows 本地访问校验

从 `0.2.0-alpha.2` 起，Windows 版首次使用需要手动输入 QQ 号。
界面明确说明用途与持久化行为，不伪装成登录、课表同步或其他功能。
`0.2.0-alpha.3` 简化首次启动页，将详细用途与持久化说明放入默认折叠的
“校验说明”中；号码输入框和继续按钮直接显示。
号码仅在本地计算 SHA-256 并与代码中的固定摘要比对，不保存原始号码，也不上传。

此功能只比对用户填写的字符串，不验证 QQ 账号归属。SHA-256 是摘要，
不是可逆加密；本地校验不能阻止填写其他号码、穷举摘要、修改程序或删除注册表标记。

## 行为

- 首次校验前，不挂载课表界面；Rust 端也拒绝读取、保存与订阅下载命令。
- 未命中限制时，保存校验完成状态，下次启动无需再输入。
- 命中限制时，保存拦截标记并显示应用内拦截弹窗；点击“退出程序”后关闭。
  之后启动直接显示同一弹窗，不加载课表界面，也不再询问 QQ 号。
  `0.2.0-alpha.4` 使用应用配色和卡片样式，文案为“你已被开发者拉入黑名单，请及时联系开发者”。
- 安装程序在界面初始化和文件安装前检查拦截标记；静默安装也会检查并返回退出码 77。
  安装程序尚未运行应用，此阶段使用安装器弹窗；已运行的应用不再使用 Windows 消息框。
- 卸载程序保留访问状态，重新安装仍检查；不修改 QQ 客户端、聊天记录或其他软件的数据。
- macOS SwiftUI 应用不受影响；Fedora 的 Rust 版直接放行，不要求 QQ 号。

## 注册表与维护

当前 Windows 用户、64 位注册表视图：

```text
HKEY_CURRENT_USER\Software\CampusGoUltra\AccessControl
    Verified    REG_DWORD    1
    Blocked     REG_DWORD    1
```

`Blocked` 只检查是否存在，不依赖类型或内容；它的优先级高于 `Verified`。
状态读取或写入失败时会显示错误，不把失败当成通过。
标记只作用于当前 Windows 用户，不是整台机器的全局封禁。

需要由设备使用者或维护人员解除限制时，可明确执行：

```powershell
Remove-ItemProperty -LiteralPath 'HKCU:\Software\CampusGoUltra\AccessControl' -Name Blocked
```

需要重新测试首次输入时，可另行删除同一位置的 `Verified` 值。
自动测试使用独立测试键；安装与启动检查会备份并恢复实际访问状态。
